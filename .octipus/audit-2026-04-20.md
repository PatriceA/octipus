## 1. DESIGN.md — compliant with 3 documented gaps

Overall verdict: the shipped work upholds the eight core principles (fail loud, small core, observability, typed contracts, durable-vs-ephemeral, two-view, local-first, eval-in-CI). Three issues worth tracking.

### Findings

- **COMPLIANCE WIN — Fail loud, KB self-check.**
  `src/core/rag/health.ts:49-171` performs startup DB + embedding + vector-write probe and caches a readiness report. `kbNotReadyResponse()` returns 503 with a specific reason; `logger.error` fires on failure with concrete fix hints. Exemplary "fail loud" — no silent fallback, surfaces the reason to the user via the web banner.

- **COMPLIANCE WIN — Typed contracts, structured error taxonomy.**
  `src/core/errors/classification.ts:16-54` introduces `FailoverReason` (24 enumerated values) and `RecoveryAction` (8 values). All 8 model providers (`src/models/providers/*`) migrated off ad-hoc string-matching — matches the "typed contracts" principle and eliminates the string-matching hazard flagged by Hermes-derived categories.

- **COMPLIANCE WIN — Durable vs ephemeral separation.**
  `swarm_nodes` (durable; `src/db/schema/swarm-nodes.ts`) carries the tree; `SwarmCallGraph` (in-memory; `src/core/swarm/call-graph.ts`) carries the fingerprint set. Trajectory recorder writes to disk JSONL + a `trajectory_runs` pointer row. Correctly aligned with DESIGN.md §"Durable where it matters, ephemeral where it helps".

- **GAP — No special cases / small core: `spawn_worker` + `spawn_team` still registered.**
  `src/core/orchestrator/meta-tools.ts:49-160` still wires legacy `spawn_worker` and `spawn_team` alongside `spawn_child`. Design principle "No special cases" says the core should stay small; the swarm-design decision #2 explicitly called for a clean break. Logged as `[deprecation]` but functional. Action: complete deprecation or move to a separate "legacy-compat" module.

- **MISSING DOCUMENTATION — DESIGN.md does not acknowledge Swarm.**
  DESIGN.md §"Recursive composability" mentions pipelines-as-nodes but not the 3-level Orchestrator/Agent/Subagent hierarchy that now lives in `src/core/swarm/` with its own spawner, call-graph, budget envelope, and gateway events. The design is captured in `.octipus/swarm-design.md` (501 lines) but that file is not discoverable from DESIGN.md and is not part of the public docs set. Action: either promote swarm to a dedicated section in DESIGN.md (it is now load-bearing and parallel to pipelines), or add a one-line reference from DESIGN.md to `.octipus/swarm-design.md`.

## 3. SECURITY.md — 1 violation, 2 compliance wins

Overall: the permission-intersection model and cascade-cancel in swarm hold up well. The security preamble and input guard are load-bearing but underused on the swarm path. One concrete violation.

### Findings

- **VIOLATION — Swarm child briefs bypass `guardInput`.**
  `.octipus/swarm-design.md:148` explicitly states: "`taskBrief` + `parentSummary` → existing `guardInput` (`src/core/orchestrator/input-guard.ts`) before becoming child user message. Poisoned upstream tool output can't smuggle instructions down." The implementation in `src/core/swarm/spawner.ts:261` calls `composeChildMessage(brief)` (line 755) without running `guardInput` on the inputs. `src/core/swarm/` contains zero references to `guardInput` or `input-guard`. Concrete attack surface: a compromised upstream tool result that ends up in the parent's `metadata.parentSummary` or `taskBrief` is injected verbatim into a child's user message. Matches the prompt-injection category in SECURITY.md §"In scope". Action: add `guardInput` (or at minimum `buildSecurityReminder`) to the brief composition path in `spawner.ts`.

- **COMPLIANCE WIN — Permission inheritance is intersection.**
  Swarm design and implementation both enforce `child.allowedToolIds = parent.allowedToolIds ∩ requiredToolIds`. Matches SECURITY.md §"Permission escalation" — child cannot widen its tool surface beyond its parent.

- **COMPLIANCE WIN — MCP circuit breaker limits blast radius.**
  `src/mcp/circuit-breaker.ts` trips a failing MCP server into `open` after 3 consecutive failures, caps at 5 min cooldown. Aligned with the "fail loud" principle and prevents an unavailable MCP endpoint from dragging every tool call into retry storms.

- **FLAG — Trajectory JSONL files store request/response pairs on disk unencrypted.**
  `src/core/trajectories/recorder.ts` writes to `${workspace.rootPath}/trajectories/YYYY-MM-DD.jsonl`. PII filter runs on `userMessage` + `finalResponse` (emails, phone numbers) but SSN/credit-card/API-key/IP categories from the full `filter_pii` are not applied on the recorder path. The file header comment acknowledges this gap. Attack surface is local-only (filesystem access = out of scope per SECURITY.md §"Out of scope"), but a backup/export pathway that ships these files elsewhere would leak. Action: either narrow the recorder's PII filter to match the full `filter_pii` breadth, or gate trajectory export on a fresh full-scrub pass.

- **FLAG — Skill proposal prompts are user-editable via `/skills/proposals`.**
  `skill_proposals.draftPromptTemplate` is user-editable text that eventually gets promoted into a `skills` table row and injected into role system prompts. The promotion path should run the same output-guard + template-injection checks the existing skill import path runs. Not a VIOLATION yet because promotion is still manual, but worth checking before the proposal UI is fleshed out.
