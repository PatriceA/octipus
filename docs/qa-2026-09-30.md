# QA fixes — 30 September 2026

## Learning

The review worker explicitly requested **4,000 output tokens**, overriding the
model's configured default. Reasoning models can consume that budget before
finishing the JSON review. The provider maximum of 131,072 is a ceiling, not
the requested budget; the schema default for requests is 16,384.

The worker now uses the configured default, limited by the provider maximum
and estimated remaining context. A length-limited response gets one retry at
up to twice the initial request budget, before any writes. Continued truncation
reports the model, budget, output and reasoning usage. The prompt requests a
small JSON result. This does not change the global model setting.

Reviews already run after completed plan steps, full plan completion and
substantial turns, and can be triggered manually. Evidence includes recorded
execution and verification events, messages and plan information; narration
is not required. Successful reviews can save knowledge and memory or propose
skills, subject to existing permissions, validation and deduplication.
Old failed checks remain visible; use **Check recent work** after updating.

### Hermes comparison

[Hermes background review](https://github.com/NousResearch/hermes-agent/blob/main/agent/background_review.py)
uses a separate review run over a conversation snapshot including tool activity.
It restricts available tools, records actual write receipts, bounds review
iterations and aggregate input, and can defer work when foreground activity
resumes. Matching the parent model preserves cache reuse; a different review
model receives a digest.

Octipus already has a separate bounded evidence review, milestone triggers,
validated sources, write outcomes and deduplication. The immediate change here
is to respect model budgets and keep the review output compact. Useful future
work is foreground-aware deferral and explicit proposals to amend an existing
skill. Those extensions are not implemented in this patch. Copying a whole
multi-day CLI transcript would increase cost and is not necessary to fix this
failure.

## Interface and permissions

- **Secrets:** configured provider credentials remain visible; unused provider
  setup opens through Add connection. OAuth setup is collapsed separately;
  channels and custom vault entries have their own sections.
- **Models:** CLI configuration is collapsed by default.
- **MCP:** Allow/Ask/Deny can be applied to all tools on one server. MCP tools
  default to Allow; explicit policies and administrator rules still take
  precedence. Bulk changes replace personal scope/expiry restrictions, as
  stated beside the controls. The Tools page links to this single MCP editor.
- **Persona:** the default Octipus voice prompt is reduced to seven focused
  lines. Execution and delegation rules remain in the role instructions.
- **Skills:** mounted skills support role assignments without modifying their
  source files. A migration permits external IDs in the assignment table and
  retains cleanup when database skills are deleted. Identical complete bundles
  are merged with source aliases preserved. Same-named bundles with different
  scripts or content remain separate, including genuinely different Claude and
  Codex versions. The category badge is explicitly labelled; category
  `general` is not an automatic General-role assignment.
  **Reload mounted skills** reads source changes on demand without polling or
  a backend restart. It refreshes the list and assignments; instructions already
  loaded into an agent's context are not replaced retroactively.

## Chat ordering and rate limits

Visible message timestamps survive REST acknowledgement so clock differences
cannot move a user's message across its agent card. File groups use the owning
agent's timeline position instead of the latest file event's timestamp.

The old ten-second refresh fetched events for every historical agent and
drained every available page. A session with 58 agents could therefore make
hundreds of requests per minute with only one agent actually running.
Overlapping refreshes made the problem worse.

Refreshes now have an in-flight guard and fetch at most four event pages per
cycle. Finished agents stop being polled after their tail is confirmed;
hidden tabs pause polling. A 429 response pauses browser reads according to
Retry-After, with a fallback delay. Existing messages stay visible. A small
inline status explains the pause and automatic recovery; it does not imply
that the running agent stopped.

## CocoIndex

The previous local path uses Python Sentence Transformers/PyTorch with
Snowflake's arctic-embed-xs. Its [model card](https://huggingface.co/Snowflake/snowflake-arctic-embed-xs)
lists 22 million parameters and 384 dimensions. Float32 weights alone would
be approximately 88 MB; Python, PyTorch, tokenizer, batches and index require
additional memory, and installed dependencies can occupy much more disk.

The connector now offers the configured **Octipus embedding model** as an
alternative. Its [supported LiteLLM configuration](https://github.com/cocoindex-io/cocoindex-code/blob/main/EMBEDDINGS.md)
connects to an authenticated local Octipus embedding endpoint. Octipus applies
document/query prefixes and the configured provider settings. Requests are
serialized into batches of eight; local embedding threads are limited to two.
Shared mode does not install or load a separate Sentence Transformers model.
If the selected Octipus provider is remote, code text goes to that provider.

Changing embedding identity requires applying settings again and rebuilding
the managed index. Existing local installations retain their selected mode.
The initial indexing timeout was already two hours; simply increasing it
would not fix RAM pressure. The original timeout has not been reproduced with
the user's full repository collection, so a specific out-of-memory cause is
not claimed. Live provider integration and large-index memory use still need
validation on that installation.

## Updating

`octi update --dry-run` previews the detected installation path. Repository
installs update their existing upstream with fast-forward-only Git, refuse
dirty checkouts, install locked dependencies and build all components. A
published global npm installation updates its own package. Private source
snapshots without Git are not guessed to be a similarly named npm package;
they receive an installer-specific explanation. Restart remains explicit.
The Windows terminal banner is centered.

No live service restart, database repair, paid learning rerun or provider
indexing run is part of this change. Tests use isolated databases and mocked
providers/API responses.
